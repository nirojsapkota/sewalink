```ruby
class PlatformSetting < ApplicationRecord
  DEFAULT_COMMISSION_RATE = BigDecimal("0.10")

  validates :key, presence: true, uniqueness: true

  def self.commission_rate
    value = find_by(key: "commission_rate")&.value
    value.present? ? BigDecimal(value) : DEFAULT_COMMISSION_RATE
  end

  def self.set_commission_rate(rate)
    setting = find_or_initialize_by(key: "commission_rate")
    setting.value = BigDecimal(rate.to_s).to_s
    setting.save!
    setting
  end
end
```

```ruby
class Admin::BaseController < ApplicationController
  layout 'admin'
  before_action :authenticate_user!
  before_action :ensure_admin!

  private

  def ensure_admin!
    redirect_to root_path, alert: "Access denied. Admin only." unless current_user&.admin?
  end

  def log_admin_action!(action, target = nil, details: {})

  end
end
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Admin browser → Admin::BaseController | Only `current_user.admin?` may reach any admin controller; all Wave 2 controllers inherit this gate. |
| Admin action → Task/User/Bid/Category mutation | Destructive/financial state changes (suspend, force-cancel, unassign, reopen) must be attributable to a specific admin. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|--------------|------------------|
| T-09-01 | Spoofing | Admin::BaseController | mitigate | `ensure_admin!` before_action already gates every admin controller; no change needed, verified by existing dashboards_spec.rb pattern reused in Wave 2 specs. |
| T-09-02 | Repudiation | All Wave 2 destructive actions | mitigate | `log_admin_action!` helper added here writes an `AdminActivityLog` row (admin_id, action, target) for every suspend/reject/force-cancel/reopen/settings-update call in Wave 2 plans. |
| T-09-03 | Tampering | `config/routes.rb` admin namespace | mitigate | Routes scoped to `:edit`/`:update`/named member actions only — no unscoped `resources :users` that would expose `:destroy` on User records. |
| T-09-04 | Elevation of Privilege | `PlatformSetting.set_commission_rate` | accept | Only reachable via Admin::SettingsController (Wave 2), itself gated by `ensure_admin!`; no additional risk introduced at this layer since this plan only defines the model. |
</threat_model>
