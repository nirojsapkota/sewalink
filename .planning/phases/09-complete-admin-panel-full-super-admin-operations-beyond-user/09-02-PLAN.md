Rewrite `app/controllers/admin/users_controller.rb`:
```ruby
class Admin::UsersController < Admin::BaseController
  before_action :set_user, only: [:show, :edit, :update, :suspend, :reactivate]

  def index
    @users = User.order(created_at: :desc)
    @users = @users.where("phone LIKE ?", "%#{params[:query]}%") if params[:query].present?
    @users = @users.page(params[:page]).per(20)
  end

  def show
    @tasks_posted = @user.tasks.count
    @tasks_completed_as_tasker = Task.joins(:accepted_bid).where(bids: { user_id: @user.id }).where(status: :completed).count
    @tasks_completed_as_poster = @user.tasks.completed.count
  end

  def edit
  end

  def update
    if @user.update(user_params)
      log_admin_action!("update_user", @user, details: { changes: user_params.to_h })
      redirect_to admin_user_path(@user), notice: "User updated successfully."
    else
      render :edit, status: :unprocessable_entity
    end
  end

  def suspend
    if @user == current_user
      redirect_to admin_user_path(@user), alert: "You cannot suspend your own account." and return
    end

    @user.suspend!(params[:suspension_reason].presence || "No reason provided")
    log_admin_action!("suspend_user", @user, details: { reason: @user.suspension_reason })
    redirect_to admin_user_path(@user), notice: "User suspended."
  end

  def reactivate
    @user.reactivate!
    log_admin_action!("reactivate_user", @user)
    redirect_to admin_user_path(@user), notice: "User reactivated."
  end

  private

  def set_user
    @user = User.find(params[:id])
  end

  def user_params
    params.require(:user).permit(:first_name, :last_name, :bio, :locale, :admin, :active_role)
  end
end
```
Note strong params deliberately exclude `:phone`, `:email`, `:encrypted_password`, `:otp_secret` to prevent mass-assignment of authentication-sensitive fields.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Admin browser → Admin::UsersController#update | Admin can grant/revoke `admin` flag and change `active_role` on ANY user, including escalating privileges. |
| Admin browser → Admin::UsersController#suspend | Suspension blocks login (Devise `active_for_authentication?`); must not be self-applicable to avoid admin lockout. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|--------------|------------------|
| T-09-05 | Elevation of Privilege | `Admin::UsersController#update` (`admin` flag mass-assignment) | mitigate | Only reachable behind `ensure_admin!`; strong params intentionally include `:admin` since granting admin access is an explicit ADMIN-05 requirement — every change is written to `AdminActivityLog` for traceability (`log_admin_action!("update_user", ...)`). |
| T-09-06 | Denial of Service | `Admin::UsersController#suspend` | mitigate | Explicit guard `if @user == current_user` prevents an admin locking themselves out; covered by Test 3. |
| T-09-07 | Repudiation | suspend/reactivate/update actions | mitigate | Every action calls `log_admin_action!`, persisting admin_id + action + target + details (reason for suspend). |
| T-09-08 | Tampering | `user_params` strong params | mitigate | `:phone`, `:email`, `:encrypted_password`, `:otp_secret` explicitly excluded from permitted params — cannot be mass-assigned via this form. |
</threat_model>
