Rewrite `app/controllers/admin/tasks_controller.rb`:
```ruby
class Admin::TasksController < Admin::BaseController
  before_action :set_task, only: [:show, :edit, :update, :force_cancel]

  def index
    @tasks = Task.includes(:user, :category, :tasker).order(created_at: :desc)
    @tasks = @tasks.where(status: params[:status]) if params[:status].present?
    @tasks = @tasks.page(params[:page]).per(20)
  end

  def show
    @task = Task.includes(:user, :category, :tasker, :payment_transactions, :reviews, :dispute_evidences).find(params[:id])
  end

  def edit
  end

  def update
    if @task.update(task_params)
      log_admin_action!("update_task", @task, details: { changes: task_params.to_h })
      redirect_to admin_task_path(@task), notice: "Task updated successfully."
    else
      render :edit, status: :unprocessable_entity
    end
  end

  def force_cancel
    previous_status = @task.status

    if @task.esewa? && @task.paid? && !@task.cancelled? && !@task.completed?
      Payments::LedgerManager.refund_poster(@task)
    end

    @task.cancel!
    log_admin_action!("force_cancel_task", @task, details: { previous_status: previous_status })
    redirect_to admin_task_path(@task), notice: "Task force-cancelled."
  rescue AASM::InvalidTransition
    redirect_to admin_task_path(@task), alert: "Task cannot be cancelled from its current status (#{@task.status})."
  end

  private

  def set_task
    @task = Task.find(params[:id])
  end

  def task_params
    params.require(:task).permit(:title, :description, :budget, :category_id, :location)
  end
end
```
Note: `task.cancel!` (bang AASM event) raises `AASM::InvalidTransition` when the guard/state doesn't allow the move (e.g., from `completed`); the rescue converts this into a friendly redirect rather than a 500.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Admin browser → Admin::TasksController#update | Admin can override task financial fields (budget) and category — must not allow status transitions via raw mass-assignment. |
| Admin browser → Admin::TasksController#force_cancel | Triggers a real ledger refund transaction; must be idempotent-safe and logged. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|--------------|------------------|
| T-09-09 | Tampering | `task_params` strong params | mitigate | `:status`, `:user_id`, `:payment_type` excluded from permitted params — status changes only via the dedicated `force_cancel` action, never via raw `update`. |
| T-09-10 | Repudiation | `force_cancel`/`update` actions | mitigate | Both call `log_admin_action!` recording admin_id, action, task id, and prior status/changed fields. |
| T-09-11 | Tampering (financial) | `Payments::LedgerManager.refund_poster` invocation | mitigate | Only invoked when `@task.esewa? && @task.paid?` and guarded by the AASM `cancel!` transition — invalid-state cancels raise `AASM::InvalidTransition`, caught and surfaced as a friendly alert instead of executing a double-refund. |
</threat_model>
