<objective>
Install `rolify` and make admin-panel access role-driven instead of boolean-driven. Add the `roles` / `users_roles` tables, migrate every existing `admin: true` user to hold the `super_admin` role, and rewrite `Admin::BaseController#ensure_admin!` to check roles. The legacy `admin` boolean column stays in the schema (not dropped) but stops being the source of truth for access control.

Purpose: This is the foundation for ADMIN-12 — granular, assignable admin roles (`super_admin`, `accountant`) replacing the single boolean flag, with zero access-loss during migration.
Output: `rolify` installed and migrated, `Role`/`User` models wired, `Admin::BaseController` gated on roles, existing admin-flagged users preserved as `super_admin`, factory traits updated so the existing admin request-spec suite keeps passing.
</objective>

      def up
        User.where(admin: true).find_each do |user|

        # Intentionally a no-op: do not strip roles on rollback, this would be

## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Browser session → Admin::BaseController | Authenticated (Devise) but not-yet-authorized request reaching any `/admin/*` route |
| Data migration → production users table | One-time migration converting a boolean flag into role rows; must not silently drop or duplicate access |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|--------------|------------------|
| T-10-01 | Elevation of Privilege | `Admin::BaseController#ensure_admin!` | mitigate | Access gated on `current_user&.admin_access?` (role-based), not the legacy boolean; covered by access_control_spec Test 3/4 |
| T-10-02 | Tampering | Legacy `admin` boolean column | mitigate | Boolean is fully decoupled from access decisions after this plan — flipping it has zero effect on `/admin` access, verified by Test 4 (`admin: true` + no role = denied) |
| T-10-03 | Repudiation | Data migration (Task 2) | accept | Migration is idempotent (`unless user.has_role?(:super_admin)`) and irreversible on rollback by design (no destructive role-stripping on `down`), documented in migration comment |
| T-10-04 | Denial of Service | Migration failure mid-run | accept | `find_each` batches and per-row idempotency mean a re-run after a partial failure is safe and low-risk for this admin-only, low-volume users table |
</threat_model>
