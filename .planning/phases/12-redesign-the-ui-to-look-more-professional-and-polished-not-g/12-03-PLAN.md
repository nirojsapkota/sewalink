<objective>
Redesign the secondary flows (D-10 priority 3): messaging (conversations/live_chats/messages), profiles, reviews, onboarding, payments checkout, dispute evidence submission, and all Devise auth views (users/*). This is Wave 3 of 4, executed after Wave 2 (core flows) lands.

Purpose: These are lower-traffic but still user-facing pages; the login/registration/password views in particular are often a new user's very first impression and must match the "Modern Neutral SaaS" direction, not the old purple template.
Output: Slate/indigo-token-based, helper-driven markup replacing all purple hex/glow/bounce styling in these 22 files. Mailer views remain explicitly out of scope (see note below).
</objective>

## Color/Class Migration Map (same table as Plans 01/02 — apply identically here)

| Old pattern | New pattern |
|---|---|
| `#7C3AED` (bg/text/border) | `indigo-600` |
| `#6D28D9` (hover) | `indigo-700` |
| `#4C1D95` full opacity | `slate-900` (headings) or `slate-700` (body/label) |
| `#4C1D95/70` | `slate-600` |
| `#4C1D95/60` | `slate-500` |
| `#4C1D95/40` | `slate-400` |
| `#4C1D95/20` (border) | `slate-200` |
| `#4C1D95/10`, `#4C1D95/5` | `slate-100` |
| `#FAF5FF` | `white` or `slate-50` |
| `#F3E8FF` (chip/badge bg) | `slate-100` (or `indigo-50` for "info" pills) |
| `#E9D5FF` (chip hover bg) | `slate-200` |
| `font-['Mukta']` | remove (inherits `@theme` font-sans) |
| `hover:-translate-y-*`, `active:translate-y-*`, `hover:scale-*`, `active:scale-*` | remove entirely |
| `backdrop-blur-*` | remove entirely |
| `shadow-lg`/`shadow-xl`/`shadow-2xl` at rest | `shadow-sm` (cards) or removed (buttons) |
| `animate-pulse` (decorative) | remove |
| `font-black`/`font-extrabold`/`font-bold` | `font-semibold` (600 max) |
| Ad-hoc button classes | `button_class(:primary\|:secondary\|:destructive\|:ghost)` |
| Ad-hoc card wrapper classes | `card_class` / `card_class(interactive: true)` |
| Ad-hoc input/select/textarea classes | `input_class` |
| Ad-hoc status/role pill classes | `status_badge_class(status)` where applicable, else `bg-slate-100 text-slate-700` (neutral) |

## Contact-masking constraint (SAFE-06, must not regress)

`app/views/conversations/show.html.slim`, `app/views/live_chats/_task_preview.html.slim`, `app/views/live_chats/show.html.slim`, and `app/views/messages/_message.html.slim` implement phone/email contact masking (existing Phase 5/8 feature). This plan is VISUAL ONLY — do not change any Ruby logic, masking regexes, or conditional `if`/`unless` blocks that determine what content is shown; only change `class:` attribute values and static wrapper markup (e.g. converting a bare `div` to use `card_class`).
