# Phase 12 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — Rails + Slim + Tailwind CSS v4 (`tailwindcss-rails` gem), no component framework. shadcn/ui is not applicable (this is not a React/Next/Vite project); the shadcn initialization gate is skipped by design. |
| Preset | not applicable |
| Component library | none installed (`view_component` gem absent per D-09). Design system is implemented as (a) Tailwind v4 `@theme` tokens in `app/assets/tailwind/application.css`, and (b) a small set of shared Slim partials under `app/views/shared/` (e.g. `_button.html.slim`, `_card.html.slim`, `_badge.html.slim`) introduced by this phase to replace ad-hoc hex-coded utility classes. |
| Icon library | None currently installed — icons are hand-written inline `<svg>` (Heroicons-outline visual style, 24x24 viewBox, `stroke="currentColor"`, `fill="none"`, 1.5–2px stroke width). **Decision (agent discretion, D-13):** keep this pattern — do NOT add an icon gem/CDN dependency. Continue hand-authoring Heroicons-outline-style inline SVGs (copy paths from heroicons.com/outline as needed) for consistency. All icons must share the same stroke width (1.5) and viewBox convention. Never use emoji as icons. |
| Font | **Inter** (Google Fonts, weights 400/600), replacing "Mukta". Fallback stack: `Inter, "Noto Sans Devanagari", ui-sans-serif, system-ui, sans-serif`. `Noto Sans Devanagari` is added as an explicit fallback so Nepali-locale text (which Inter does not cover — Inter is Latin/Cyrillic/Greek only) renders correctly via the fallback rather than an ugly system default. "Atkinson Hyperlegible" `<link>` import is dropped from all layouts (D-08 resolved: it is imported in `application.html.slim` and `landing.html.slim` but never referenced by any `font-` class anywhere in the codebase — confirmed via grep — so it is dead weight). |

## Spacing Scale

Declared values (must be multiples of 4, Tailwind defaults — no custom spacing scale needed):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, badge inner padding |
| sm | 8px | Compact stacked elements (form label → input gap) |
| md | 16px | Default component padding, card inner padding (mobile) |
| lg | 24px | Card inner padding (desktop), section padding (mobile) |
| xl | 32px | Section padding (desktop), gaps between major page blocks |
| 2xl | 48px | Section-to-section breaks on landing/dashboard pages |
| 3xl | 64px | Hero/top-of-page spacing, landing page section separation |

Exceptions:
- Icon-only buttons / tap targets: minimum 44×44px hit area regardless of visual icon size (mobile / Hotwire Native touch target requirement, D-11) — pad a smaller icon to reach 44px rather than shrinking the tap target.
- Navbar height stays at existing `py-4` (16px vertical) for content, not on the 8-point major scale — acceptable as a chrome-level exception since it's a fixed, single-use pattern, not a repeated component.

## Typography

Exactly 4 sizes, exactly 2 weights (regular 400, semibold 600) — matches "Linear/Notion" restrained typographic style.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px (`text-base`) | 400 (regular) | 1.5 |
| Label / small | 14px (`text-sm`) | 400 (regular); 600 (semibold) for emphasized labels/badges | 1.4 |
| Heading (H2/H3, section titles, card titles) | 20px (`text-xl`) | 600 (semibold) | 1.25 |
| Display (H1, hero headline, page title) | 28px (`text-3xl`, scale to `text-4xl`/36px only on landing hero at `md:` breakpoint) | 600 (semibold) | 1.15 |

Rules:
- Never use font-weight 700/800/900 (Mukta's `wght@800` and current bold CTAs must be dialed back to 600 max) — this is a key signal of the "generic AI template" look this phase is correcting (D-03).
- Never introduce a 5th font size. If a view currently uses `text-lg`, `text-2xl`, or arbitrary sizes, map it to the nearest of the 4 roles above.
- Body text color: `slate-600`. Headings: `slate-900`. Muted/secondary text (timestamps, helper text): `slate-500`.

## Color

"Modern Neutral SaaS" palette — slate neutrals dominant, indigo as the sole accent, standard semantic colors kept as-is (D-06).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` (white) page background; `slate-50` (`#F8FAFC`) for subtly recessed sections (e.g. mobile nav strip, alternating landing sections) | Page backgrounds, main content surfaces |
| Secondary (30%) | `slate-100` (`#F1F5F9`) for cards/panels background alt state; `white` cards with `slate-200` (`#E2E8F0`) borders as the primary card treatment; `slate-900` (`#0F172A`) for admin sidebar/nav chrome if a dark chrome is desired — **decision: keep navbar white/`slate-50`, not dark**, to stay consistent across public + admin (D-13) | Cards, navbar, footer, admin sidebar, table row stripes |
| Accent (10%) | `indigo-600` (`#4F46E5`), hover state `indigo-700` (`#4338CA`), subtle tint `indigo-50` (`#EEF2FF`) for selected/active backgrounds | **Reserved exclusively for:** primary CTA buttons (e.g. "Post a Task", "Place Bid", "Sign Up", "Submit"), active nav-link indicator/underline, focus rings (`ring-indigo-600`), links within body text, active role badge, selected filter/tab state, progress indicators tied to primary flow. NOT used for: decorative blobs/gradients, card backgrounds, icon-chip backgrounds on every card (pick slate-100 there instead), section dividers. |
| Destructive | `red-600` (`#DC2626`), hover `red-700` (`#B91C1C`) | Logout, delete/force-cancel task, suspend/reactivate-to-suspend, reject bid, dispute-refund actions only |

Additional kept semantic colors (D-06, unchanged from current usage, restyled to standard Tailwind shades instead of arbitrary hex):
- Success / online / completed: `green-600` (`#16A34A`), tint `green-50` for badges
- Warning / pending: `amber-600` (`#D97706`), tint `amber-50` for badges
- Info (rarely needed): `slate-600` — do not introduce a second blue; indigo already serves as the single accent/brand blue-purple.

Accent reserved for: primary CTA buttons, active nav indicator, links, focus rings, active/selected states, primary progress/step indicators. Never used as a full-bleed background, never used for more than one prominent element per screen section.

## Component Patterns

Concrete rules for the shared partials to introduce (D-09), replacing arbitrary hex-coded inline classes.

### Buttons
- **Primary** (`shared/_button_primary` or a `btn_classes(:primary)` helper): `bg-indigo-600 text-white hover:bg-indigo-700 px-5 py-2.5 rounded-lg text-sm font-semibold transition-colors duration-150`. No shadow by default; no `hover:-translate-y-*`, no `active:scale-*`. Focus: `focus-visible:ring-2 focus-visible:ring-indigo-600 focus-visible:ring-offset-2`.
- **Secondary/outline**: `bg-white text-slate-700 border border-slate-300 hover:bg-slate-50 px-5 py-2.5 rounded-lg text-sm font-semibold transition-colors duration-150`.
- **Destructive**: same shape as primary, `bg-red-600 hover:bg-red-700 text-white`.
- **Ghost/tertiary** (nav links, text actions): `text-slate-600 hover:text-slate-900 text-sm font-medium transition-colors duration-150` — no background.
- All buttons/links that trigger an action: `cursor-pointer` explicit even on `<button>` (Safari/consistency), minimum 44px tap height on mobile.
- Border radius standard: `rounded-lg` (8px) for buttons/inputs, `rounded-xl` (12px) for cards, `rounded-full` only for avatars/status dots/pills (badges, role-toggle chip).

### Cards
- `bg-white border border-slate-200 rounded-xl p-6` (desktop) / `p-4` (mobile). Shadow: `shadow-sm` only, no `shadow-lg`/`shadow-xl`/`shadow-2xl` at rest. On hover (only for clickable/navigable cards like task listings): `hover:border-slate-300 hover:shadow-md transition-shadow duration-150` — no translate/scale.
- Card title: Heading role (20px/600/slate-900). Card body: Body role (16px/400/slate-600).

### Forms / Inputs
- `border border-slate-300 rounded-lg px-4 py-2.5 text-base text-slate-900 placeholder:text-slate-400 focus:outline-none focus:ring-2 focus:ring-indigo-600 focus:border-indigo-600 transition-colors duration-150`.
- Labels: 14px/600/slate-700, `mb-1.5` above the input.
- Validation error text: 14px/400/`red-600`, below the field.
- Disabled state: `bg-slate-50 text-slate-400 cursor-not-allowed`.

### Badges / Status Pills
- Shape: `inline-flex items-center rounded-full px-2.5 py-0.5 text-xs font-semibold`.
- Status color pairs (bg tint / text): success `bg-green-50 text-green-700`; warning `bg-amber-50 text-amber-700`; destructive/dispute `bg-red-50 text-red-700`; neutral/draft `bg-slate-100 text-slate-700`; info/in-progress `bg-indigo-50 text-indigo-700` (acceptable minor accent use since it's a small pill, not a dominant surface).

### Navigation (navbar — highest priority per D-10)
- Background: `bg-white` with `border-b border-slate-200` (remove `backdrop-blur-md`, `shadow-sm`, and the `/5` opacity purple border).
- Logo link: remove `hover:opacity-90 active:scale-95 transform` — replace with no transform, optional `transition-opacity duration-150 hover:opacity-80` only if a hover affordance is wanted.
- Nav links: Ghost/tertiary button style above; active link gets `text-indigo-600 font-semibold` (no underline animation, no scale).
- Role-toggle chip: keep the pill shape but restyle — `bg-slate-100 text-slate-700 hover:bg-slate-200 rounded-full px-3 py-1.5 text-xs font-semibold transition-colors duration-150` (drop `hover:-translate-y-0.5`, `shadow-sm hover:shadow-md`, purple `#F3E8FF`/`#7C3AED`). Keep the green online-status dot (`bg-green-500`) but drop `animate-pulse` (a single persistent pulsing dot everywhere reads as noisy/generic — dot displays as a plain static indicator).
- Logout: `text-sm font-semibold text-red-600 hover:text-red-700 transition-colors duration-150` — drop `hover:scale-105 active:scale-95`.
- Mobile language row: `bg-slate-50` (not `#FAF5FF`) with `border-t border-slate-200`.

### Layout Chrome (footer, flash/notifications — D-10 priority 1)
- Footer: `bg-white border-t border-slate-200 py-10` (drop `bg-white/50` translucency and purple border tint). Copyright text: `text-sm text-slate-400`.
- Flash/toast notifications: keep existing position/behavior (fixed bottom-right stack), restyle surface to `bg-white border border-slate-200 shadow-md rounded-lg` with left accent bar colored by type (green/red/amber/indigo) instead of full-color backgrounds.
- Body background: `bg-white` (or `bg-slate-50` for pages with card-grid content), `text-slate-600`, replacing `bg-[#FAF5FF] text-[#4C1D95]`.

### Admin Panel (D-10 priority 4, D-13 discretion: light pass, not full redesign)
- **Decision:** Admin gets a **tokens-and-primitives-only pass** — apply the new color tokens (slate/indigo instead of any residual purple/ad-hoc grays), the shared button/badge/card partials, and the Inter font, but do NOT redesign admin-specific layouts (tables, filter bars, sidebar structure) beyond swapping color/typography/spacing tokens onto existing structure. This matches D-10's explicit lowest-priority ordering and avoids scope creep into a 4th priority tier that CONTEXT.md marks as "already has a separate layout" and lower-traffic.

## Motion & Interaction

Direct correction of D-03 (the "generic AI-generated" tell is over-animated hover states):

- **Transitions:** `transition-colors duration-150` (or `duration-200` max) on interactive elements — color/background/border changes only.
- **Banned by default:** `hover:scale-*`, `hover:-translate-y-*`, `active:scale-*`, `animate-pulse` (except a single loading spinner use-case), `animate-bounce`, `backdrop-blur-*` on nav/hero elements, decorative `blur-3xl` gradient "blob" shapes on the landing hero.
- **Exception — legitimate loading/recording states:** the voice-assistant recording indicator (`home/index.html.slim` mic button) may keep a pulse/ring animation while actively recording, since it communicates real-time state, not decoration. Scope any remaining pulse animation strictly to that functional state.
- **Focus states:** every interactive element must have a visible `focus-visible:ring-2 focus-visible:ring-indigo-600` (or `ring-offset-2` on white backgrounds) — required for a11y regardless of the calmer default motion.
- **Reduced motion:** respect `prefers-reduced-motion` — since the new interaction language is already minimal (color/opacity transitions only, no transforms), this requires no special-casing beyond avoiding transform-based animation entirely.

## Copywriting Contract

This phase is visual-only (no content/feature changes per CONTEXT.md domain boundary), so copy strings are NOT being rewritten. This contract governs the tone/format for any NEW UI text the redesign introduces (e.g. new empty states if shared partials expose them) and confirms existing i18n keys are preserved as-is.

| Element | Copy |
|---------|------|
| Primary CTA (existing, unchanged) | "Post a Task" (`t("landing.hero.cta_post")`), "Find Tasks" (`t("landing.hero.cta_find")`) — visual restyle only, i18n keys untouched |
| Empty state heading | If a shared empty-state partial is introduced during this phase, format: "No {resource} yet" (e.g. "No tasks yet") — plain, factual, no forced cheerfulness/emoji |
| Empty state body | "{Contextual next action}." e.g. "Post your first task to get started." — must route through existing i18n (`t(...)`) with an English + Nepali key, not hardcoded |
| Error state | Keep existing Devise/Rails flash error copy as-is; restyle container only (see Layout Chrome above) — no copy changes |
| Destructive confirmation | Logout: no confirmation dialog (existing behavior, low-risk, unchanged). Admin force-cancel/suspend/delete actions: keep existing native `data-turbo-confirm` browser confirm dialogs — visual restyle of the triggering button only, confirm dialog itself is browser-native and out of this phase's visual scope |

Note: All copy stays bilingual via existing `t(...)` i18n calls (D-02, code_context). No hardcoded English strings should be introduced by new shared partials — always accept copy as a block/param from the calling view so existing i18n keys pass through unchanged.
